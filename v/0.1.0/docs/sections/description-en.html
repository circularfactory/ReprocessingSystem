Reprocessing System Ontology: Description back to ToC

The Reprocessing System Ontology specialises the Circular Factory Core Ontology for the reprocessing cell of subproject C02 and reuses SOSA, PROV-O and QUDT for observations, provenance and quantity values. New terms use the namespace http://w3id.org/circularfactory/ReprocessingSystem# (prefix rps); reused terms keep their original namespaces.

Resources and capabilities

The reprocessing cell is represented as rps:SpecializedMachineCell, a cfc:Resource that comprises the manufacturing resources rps:HighSpeedDEDMachine and rps:MillTurnMachiningCentre. Both are also SOSA platforms, which host measurement systems, and SOSA actuators, which apply process parameter settings. Measurement systems such as rps:OpticalCoherenceTomographySystem, rps:TwoColourPyrometer or rps:PowderCausticAnalysisSystem are subclasses of rps:MeasurementSystem, which is both a cfc:Resource and a rps:Sensor (a specialisation of sosa:Sensor). The property rps:isCurrentlyMountedOn records on which machine a portable measurement system is currently installed. Capabilities such as rps:FullReprocessingCapability or rps:HighSpeedDEDCapability specialise cfc:EquippedCapability and are restricted to the process they enable.

Processes, operations and process runs

The process chain is modelled as subclasses of cfc:UnitPreservingProcess: rps:AdditiveSubtractiveReprocessingProcess for the complete chain, rps:HighSpeedDEDProcess for material build-up and rps:SubtractiveMachiningProcess with rps:DamageRemovalMachiningProcess and rps:FinishMachiningProcess. Process monitoring is a cfc:SupportingProcess.

Production control dispatches one rps:ReprocessingOperation per component to the cell. The operation is a composite cfc:Operation that is linked to the component by rps:reprocessesComponent and decomposed into rps:ProcessRun individuals (rps:AdditiveDepositionRun, rps:MachiningRun, rps:MonitoringRun), which are ordered by rps:hasStepOrder. Process runs are also prov:Activity, so datasets and deposited layers can be traced back to the run that generated them.

Process parameters, observations and predictions

Process parameters such as rps:LaserPower, rps:ProcessingSpeed or rps:PowderMassFlowRate are individuals of sosa:ActuatableProperty; their nominal values in a run are represented as rps:ProcessParameterSetting (a sosa:Actuation) with a qudt:QuantityValue result. Observable properties such as rps:LayerHeight, rps:MeltPoolTemperature or rps:CausticOvality are individuals of sosa:ObservableProperty with a QUDT quantity kind. They are observed on features of interest such as rps:DepositedLayer, rps:MeltPool, rps:PowderStream or rps:PowderNozzle.

Observations of physical measurement systems are rps:ProcessMonitoringObservation; estimates of data-driven process models, which are treated as virtual sensors, are rps:ModelBasedPrediction. Results are qudt:QuantityValue individuals with value, unit and, where available, standard uncertainty, coverage factor, confidence level, prediction interval and the method by which the uncertainty was evaluated (GUM Type A, GUM Type B or cross-validated prediction error).

Datasets and provenance

Raw data artifacts are represented as subclasses of rps:ProcessMonitoringDataset (a prov:Entity and rps:Measurement), for example rps:OCTMeasurementSeries or rps:PowderCausticImageStack. Only the storage location and format of the raw data are kept in the knowledge graph. rps:wasRecordedDuringProcessRun and rps:wasRecordedByMeasurementSystem specialise prov:wasGeneratedBy and prov:wasAttributedTo; rps:isComputedFromMonitoringDataset links an observation to the dataset it was derived from.

Design for future extension

Parameter settings and observations of deposit characteristics are individuals in their own right. Causal relations between process settings and the resulting component state can therefore be added in a later version without changing existing terms.

Known open issues

Version 0.1.0 contains open issues that are recorded as skos:editorialNote in the ontology: the local classes rps:Sensor and rps:Measurement pending a decision on corresponding Core classes; the alignment of the uncertainty representation with subprojects B03 and A03; a pending correction in the Core Ontology that currently makes cfc:Component unsatisfiable; the harmonisation with the Perpetual Product Ontology; and further alignments with domain ontologies. An optional module aligns the ontology with DOLCE+DnS Ultralite.
